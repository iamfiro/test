# 공부방 태그와 추천

**한 줄**: 공부방에 시험·공부 종류 태그를 달고, 내 태그와 겹치는 방을 공부방 목록 위 "추천"에 띄워
같은 목표를 준비하는 사람이 방으로 모이게 한다. `study-village.md` 결정 15.

## 0. 바뀐 이유 (2026-11-23)

처음 문서는 아이디어 원문을 "태그 페이지(멤버 목록·공부 패턴 공유)"로 풀었다. 제안자가 나중에 설명을
보탰다: **같은 태그를 단 공개 공부방이 추천에 뜨고, 태그로 다른 사람이 그 방에 올 수 있게** 하는 것이
뜻이었다. 사용자가 이 방향으로 **대신**하기로 정했다. 태그 페이지·멤버 목록·공부 패턴 공유·D-day·과목
태그는 이번 범위에서 뺐다(필요해지면 따로 결정).

## 1. 결정

| # | 주제 | 결정 |
| --- | --- | --- |
| 1 | 태그 종류 | `exam`(시험·목표)과 `kind`(공부 종류) 두 가지. **과목 태그는 없다** — 과목은 세션마다 고르는 개인 설정(지금 구현 그대로), 태그는 몇 달 단위로 준비하는 목표. 두 개념을 섞지 않는다 |
| 2 | 카탈로그 | 서버가 정규 태그와 별칭(`정처기`→`정보처리기사`)을 가진다. 입력 정규화(앞뒤 공백·`#`·대소문자·NFC) 뒤 정규 이름이나 별칭과 같으면 그 태그. 사용자는 자동완성에서 고르기만 한다 |
| 3 | 없는 태그 | 즉시 만들지 않는다. "제안"으로 저장하고 운영자가 서버 CLI로 검토해 새 태그나 기존 태그의 별칭으로 넣는다 |
| 4 | 관리 | 태그 추가·별칭·병합은 서버 CLI(관리자 화면 없음, 결정 9와 같은 방식) |
| 5 | 초기 시드 | 아래 2절 목록. 사용자가 "알아서" 정하라고 답함(2026-11-23) |
| 6 | 내 태그 | 최대 5개. **남에게 보이지 않는다** — 추천에만 쓴다 |
| 7 | 방 태그 | 방장이 같은 카탈로그에서 최대 3개. 방 카드에 보인다. 방장 편집 화면은 방 만들기·수정 화면과 함께 만든다(아직 계약 없음) |
| 8 | 추천 | `GET /study-rooms?scope=recommended`: 방 태그가 내 태그와 하나라도 겹치는 방. 정렬은 겹친 수 많은 순 → 지금 공부 중 많은 순 → 최신 순. **비밀번호 방·꽉 찬 방도 빼지 않는다**(사용자 결정). 추천 계산은 서버가 한다 |
| 9 | 방이 많아 보이게 | 사용자 요구(2026-11-23): "서비스 초기에는 최대한 방이 많아 보여야 한다". 그래서 추천은 **거르기가 아니라 위에 한 칸 더** 보여 주는 것이다. "모든 공부방"은 추천된 방도 그대로 포함한다. 겹치는 방이 없으면 큰 빈 상태 그림 대신 제목·내 태그·"태그 수정"과 한 줄 안내만 둔다. 내 태그가 없으면 태그 고르기 안내를 보인다 |

## 3. 계약 (OpenAPI 0.4.0)

| 메서드·경로 | 용도 |
| --- | --- |
| `GET /tags?q=` | 자동완성. `q`가 없으면 카탈로그 전체(종류·이름 순) |
| `GET /users/me/tags` · `PUT /users/me/tags` | 내 태그 조회·교체(`tag_ids` 최대 5, 쓰기는 `Idempotency-Key` 필수) |
| `POST /tag-suggestions` | 없는 태그 제안(`name` 1–20자, `Idempotency-Key` 필수) |
| `GET /study-rooms?scope=recommended` | 추천 방 |
| `Room.tags` | 방 태그(최대 3) |

## 4. 데이터 (서버 단계에서, 배포 체크리스트에 추가)

- `tags(id, kind, name unique, created_at)`, `tag_aliases(alias unique, tag_id)`
- `user_tags(user_id, tag_id)` 유니크, `room_tags(room_id, tag_id)` 유니크, 인덱스 `room_tags(tag_id)`
- `tag_suggestions(id, user_id, name, created_at)`
- 탈퇴 즉시 삭제(결정 2d)에 `user_tags`·`tag_suggestions` 추가. 방 삭제 시 `room_tags`도 지운다.

## 5. 테스트 (서버 단계)

- 한도: 내 태그 6번째·방 태그 4번째 거절. 없는 `tag_id` 거절.
- 멱등: 같은 키로 태그 교체를 다시 보내도 한 번만 적용, 키 없으면 거절.
- 추천: 태그가 겹치는 방만, 정렬 규칙대로, 비밀번호 방 포함, 내 태그가 없으면 빈 목록.
- 별칭: `정처기` 검색이 `정보처리기사` 하나로 나온다.
- 탈퇴: 내 태그·제안이 즉시 삭제.

## 6. 하지 않은 것

서버 코드는 아직 없다(결정 11의 F 단계). 이번에는 계약·개발 목·화면만 만든다. 방장 태그 편집은 방
만들기·수정 화면과 함께.
