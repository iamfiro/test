# 태그 기반 공부 커뮤니티 (제안)

**한 줄**: 나와 같은 공부(시험·과목·종류)를 하는 사람이 *지금* 공부하는 모습과 *어떻게* 공부하는지를
보며 의욕을 얻는 기능. 결정은 9절, `study-village.md` 결정 15로 옮겼다.

## 1. 기존 계획과 부딪치는 점 (먼저 읽기)

| 아이디어 원문 | 현재 계획 | 제안 |
| --- | --- | --- |
| "시간표 설정 기능(이미 있음)을 공유" | 결정 10: 시간표는 **뺐다**. StudyVillage에는 시간표가 없다 | 시간표 대신 **서버가 이미 가진 공부 기록**에서 만든 "공부 패턴"(시간대·요일 분포, 과목 비중)을 공유한다. 시간표 기능을 되살리지 않는다 |
| 같은 공부 하는 사람이 지금 공부 중인 게 보임 | 랭킹 인정·presence는 서버가 판정(Phase 3). 방 안 실시간 상태는 Phase 4에서 설계 | "지금 공부 중"은 **서버 presence만** 근거로 한다. 프론트가 추정하지 않는다 |
| 태그마다 커뮤니티(그룹) | 방은 정원·맵·비밀번호가 있고 한 사람은 방 하나에만 속한다 | 커뮤니티는 **방이 아니라 태그 페이지**다. 멤버십 = 태그 보유. 방 규칙과 섞지 않는다 |
| 과목 태그 | 과목·목표는 서버 사용자 설정(Phase 3), 사용자 자유 입력 | 과목 이름은 개인 데이터라 **자동으로 공개하지 않는다**. 공개 태그는 별도로 고른다 |

## 2. 범위

**포함(MVP)**
1. 태그 고르기: 내 프로필에 태그 최대 N개(제안 5).
2. 태그 페이지: 지금 공부 중 인원, 지금 공부 중인 멤버 목록, 멤버 공부 패턴.
3. 공개 범위: 태그 단위가 아니라 **두 항목**을 따로 고른다 — ① 내가 이 태그 멤버로 보이는가, ② 내 공부 패턴을 보여주는가.
4. 시험 태그 D-day(카탈로그에 시험 날짜가 있는 태그만).

**제외(이번에 안 함)**: 태그 커뮤니티 안 채팅·게시글·DM, 태그별 랭킹, 팔로우, 추천 알고리즘, 푸시 알림,
사용자가 만든 태그의 공개 검색. 필요해지면 따로 결정한다.

## 3. 동작 규칙

### 태그
- 종류 3개: `exam`(시험), `subject`(과목), `kind`(공부 종류).
- **카탈로그 방식**: 서버가 정규 태그 목록과 별칭(`정처기`→`정보처리기사`)을 가진다. 저장·표시는 정규 이름 하나.
  입력 정규화(공백·`#`·대소문자·유니코드 정규화) 후 정규 이름 또는 별칭과 일치하면 그 태그로 연결한다.
- 카탈로그에 없는 입력은 새 태그를 **즉시 만들지 않는다**(태그 분열 방지). 처리 방식은 "9절 1.
- 태그 수정·병합·시험 날짜 입력은 서버 CLI(관리자 화면 없음, 결정 9와 같은 방식).

### "지금 공부 중"
- 서버가 presence로 본 진행 중 세션이 있는 멤버만 센다. 일시정지 중은 제외(Phase 3의 presence 규칙을 따른다).
- 인원 숫자: 공개 설정과 무관하게 **태그 보유자 전체**를 센다(익명 집계). 단 숫자가 너무 작으면 개인이 특정되므로
  하한 미만(제안 3명 미만)이면 숫자 대신 "함께 공부하는 사람이 적어요" 같은 문구(앱 ARB에 없으면 문구 새로 정함).
- 멤버 목록: ①을 켠 사람만. 닉네임·캐릭터만 보인다. 과목·방·위치는 보이지 않는다.
- 전달 방식(소켓 푸시 vs 폴링)은 Phase 4의 방 실시간 상태 결정을 그대로 따른다. 이 기능에서 따로 정하지 않는다.

### 공부 패턴(시간표 대체)
- 서버가 공부 기록에서 만든 **집계만** 공유한다: 요일×시간대 분포(공부일 04:00 경계), 주간 평균 공부 시간,
  과목 비중. 개별 세션·정확한 시각은 공유하지 않는다.
- 과목 비중에는 과목 이름이 들어간다. ②를 켠 사람만, 그리고 과목을 **공개할 과목으로 따로 체크**한 것만 이름을 보인다
  (나머지는 "기타"로 합친다).
- 계산은 서버가 한다(결정 "서버가 판정하는 의미"). 프론트는 다시 계산하지 않는다.

### 시험 D-day
- 카탈로그에 `exam_date`가 있는 시험 태그에만 표시. 날짜가 없으면 D-day를 **보이지 않는다**(추정·기본값 없음).
- 날짜가 바뀌면 태그 페이지에 그대로 반영(서버 값). 시간대 기준은 IANA 시간대의 날짜.

### 개인정보·안전
- 기본값은 **비공개**(① ② 모두 꺼짐). 켜기 전에는 목록에 안 나오고 숫자 집계에만 들어간다.
- 차단한 사용자는 내 화면의 멤버 목록에서 숨김(결정 9의 차단과 같은 규칙).
- 닉네임·태그·과목명은 텍스트로만 렌더(`dangerouslySetInnerHTML` 금지).
- 탈퇴 즉시 삭제(결정 2d)에 `user_tags`·공유 설정을 추가한다.
- 미성년 이용자가 있을 수 있으므로 DM·외부 링크·자유 소개글은 넣지 않는다(제외 항목의 이유).

## 4. 데이터·API 초안

테이블(배포 체크리스트에 추가):
- `tags(id, kind, name, exam_date null, created_at)` — `name` 유니크(정규화 값).
- `tag_aliases(alias unique, tag_id)`
- `user_tags(user_id, tag_id, created_at)` — (user_id, tag_id) 유니크, 사용자당 N개 제한은 서버에서 검증.
- `user_tag_sharing(user_id, show_membership bool, show_pattern bool, shared_subject_ids[])` — 기본 모두 false.
- 인덱스: `user_tags(tag_id)`, 진행 중 세션 조회용(기존 presence 인덱스 재사용 가능한지 Phase 3에서 확인).

엔드포인트(OpenAPI 0.x 갱신, `info.version` 올림, 쓰기는 `Idempotency-Key` 필수):

| 메서드·경로 | 용도 |
| --- | --- |
| `GET /tags?query=` | 자동완성(정규 이름·별칭 매칭) |
| `GET /users/me/tags` · `PUT /users/me/tags` | 내 태그 조회·교체 |
| `GET /users/me/tag-sharing` · `PUT ...` | 공개 범위 |
| `GET /tags/{id}` | 이름·종류·D-day·지금 공부 중 인원·보유자 수 |
| `GET /tags/{id}/active-members` | 지금 공부 중인 공개 멤버 |
| `GET /tags/{id}/patterns` | 공유된 공부 패턴 집계 |

내가 가진 태그의 멤버만 `active-members`·`patterns`를 볼 수 있는지(=태그를 달아야 구경 가능) 여부는 9절 2(그 태그를 가진 사람만).
조회는 캐시 우선(ETag), 쓰기는 서버 성공 뒤에만 화면 반영(optimistic 금지).

## 5. 화면

앱에 없는 화면이다 → 앱의 기존 컴포넌트·패턴(프로필·글래스 시트·칩·통계 카드)을 따르고, 새 디자인을 만들지 않는다
(디자인 규칙의 "앱에 없는 화면"). 구성:
- 프로필/설정: 태그 칩 편집(자동완성), 공개 범위 두 스위치, 공개할 과목 선택.
- 태그 페이지: 상단에 태그 이름·D-day·지금 공부 중 N명, 아래 멤버 목록, 그 아래 공부 패턴 카드(통계 탭의 주간 막대·히트맵 컴포넌트 재사용).
- 진입점: 통계 탭 또는 방 목록 화면 한 곳(위치는 9절 3).
- 빈 상태·실패는 앱의 `empty_*.svg` 상태 그림. 문구는 새로 쓰므로 ARB에 없는 문구는 `docs/design-parity/exceptions.md`에 이유와 함께 기록.

## 6. 단계 (결정 11의 순서를 따름: 계약 → 목 화면 → 서버)

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| T0 | 결정 반영(완료) | 문서 갱신 커밋 |
| T1 | OpenAPI 초안 + 목 어댑터 + 화면(프로필 태그·공개 설정·태그 페이지) | 개발 서버에서 직접 확인, 스크린샷 |
| T2 | 서버: 태그·별칭·보유·공개 설정, 탈퇴 삭제 포함 | 테스트(아래) 통과, 계약 응답 모양 일치 |
| T3 | 서버: 지금 공부 중 집계·멤버 목록(Phase 3 presence 위에) | 두 계정으로 공부 시작/일시정지가 인원에 반영 |
| T4 | 서버: 공부 패턴 집계 + 과목 공개 | 04:00 경계·비공개 과목 합산 테스트 |
| T5 | 시험 D-day, 서버 CLI(태그 추가·별칭·병합·날짜), 배포 체크리스트 | 체크리스트 갱신 |

선행 조건: Phase 3(presence·통계·과목)와 Phase 4(공유 설정·차단) 서버가 끝나 있어야 T3~T4를 진행할 수 있다.
T1은 그 전에 목으로 먼저 가능하다.

## 7. 테스트 (서버 먼저, 실제 Postgres)

- 권한: 비공개 사용자는 목록·패턴에 안 나온다. 차단한 사용자는 내 목록에서 숨는다. 남의 공개 설정을 못 바꾼다.
- 멱등: 같은 `Idempotency-Key`로 태그 교체를 재시도해도 한 번만 적용, 키 없으면 거절.
- 한도: N+1번째 태그 거절. 별칭 입력이 정규 태그로 한 번만 저장.
- 경합: 같은 사용자의 동시 태그 교체가 일관된 결과.
- 집계: 일시정지 중은 "지금 공부 중"에서 제외, 하한 미만 인원은 숫자 대신 표시, 04:00 경계의 패턴 집계, 공개 안 한 과목은 "기타".
- 탈퇴: 태그·공유 설정이 즉시 삭제.
- 프론트: 사용자에게 보이는 동작만(태그 추가 후 목록 반영, 비공개 기본값, 서버 실패 시 입력 보존).

## 8. 위험

| 위험 | 대응 |
| --- | --- |
| 초기에 사람이 적어 태그 페이지가 비어 보임 | 숫자 하한 문구 + 큰 태그 카탈로그 시드. 사용자가 늘기 전까지는 응시자가 많은 시험 태그(`exam`) 위주로 시드 |
| 태그 분열(`정처기` 등) | 카탈로그+별칭+정규화. 신규 입력은 검토 흐름(9절 1) |
| 공부 중 여부로 사생활 노출 | 기본 비공개, 닉네임·캐릭터만, 위치·과목 비노출, 숫자 하한 |
| 비교 스트레스(남이 더 한다) | 랭킹·순위를 넣지 않고 분포·평균 집계만 |
| presence 쿼리 부하 | 태그별 집계를 짧게 캐시(서버). 간격은 Phase 4 측정 뒤 정함 |

## 9. 결정 (2026-11-23, 사용자가 추천안대로 진행하라고 답함)

1. 카탈로그에 없는 입력: 사용자 제안을 받아 서버 CLI로 검토 후 추가. 즉시 생성 없음.
2. 태그 페이지 열람: 그 태그를 가진 사람만.
3. 진입점: 통계 탭 안. **잠정** — 추천안이 없어 통계 컴포넌트 재사용 가능성으로 정했다. T1 화면에서 어색하면 다시 묻는다.
4. 태그 수 한도: 5.
5. 초기 카탈로그: 운영자가 CLI로 시드. **잠정** — 시드 목록(시험·과목·종류)은 T2 전에 사용자에게 받는다. 임의로 만들지 않는다.
6. 인원 숫자 하한: 3명 미만이면 숫자 대신 문구.
7. 시험 날짜: 운영자가 CLI로 수동 입력. 외부 연동·추측 없음.

## 10. 하지 않은 것

코드·OpenAPI·마이그레이션은 만들지 않았다. 이 문서만 추가했고 `study-village.md`는 고치지 않았다.
